# Credits

Magica tools use **progressive credit reservation**, not per-token settlement.

## Flow

1. **Send-time** — reserve a minimum hold when the message is accepted (skipped for free models).
2. **Magica tools** — after waitpoint approval (`wait.forToken`), reserve against Magica's actual `creditUsed`, then settle with an idempotent `CHARGE` keyed as `charge:tool:{toolInvocationId}`. If the balance cannot cover it, the run interrupts with **402** / `insufficient_credits`.
3. **Finalize** — release `reservedCredits - settledCredits`.

## Conversion

Magica estimate → app credits (ceil + `MAGICA_CREDIT_MARKUP`). Sub-cent Magica tools bill **1 credit**; exact microcredits stay on `ToolInvocation` for auditability. OpenRouter stays free via model policy.

## Endpoints

- `GET /api/v1/credits` — current balance
- `GET /api/v1/credits/usage` — ledger usage summary
- `POST /api/v1/tools/:name/estimate` — validate input → `{ microcredits, credits }`
